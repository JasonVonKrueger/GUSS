# AGENTS.md

## Project Overview

**GUSS (Global Update Set Studio)** is a ServiceNow scoped application that provides a developer tool for managing update set files. It renders a UI page inside ServiceNow with a tree-view sidebar that displays all artifacts in the current update set, grouped by type. Clicking an artifact opens it in a content frame.

- **Scope/Namespace:** `x_159204_guss`
- **Platform:** ServiceNow (Now SDK v4.9.2)
- **Frontend:** React 18 + TypeScript
- **Backend:** ServiceNow Fluent (server-side TypeScript compiled via `now-sdk`)

## Key Concepts

### Data Flow
1. The React app (`app.tsx`) calls `fetchUpdateSetFiles()` on mount.
2. `updateSetService.ts` POSTs to `/xmlhttp.do` using the `GussAjax` script include.
3. `GussAjax.getUpdateSetFiles()` queries `sys_update_xml` for the current update set and returns JSON.
4. The response is parsed from XML (`<answer>` element), then rendered in the `TreeView`.

### ServiceNow Artifacts
| Artifact | Type | Purpose |
|---|---|---|
| `GussAjax` | Script Include | Server-side AJAX processor; queries update set records |
| `guss_page` | UI Page | Serves the compiled React app at `x_159204_guss_main.do` |
| `gussMenu` / `gussModule` | Application Menu / Module | Navigation entry under "GUSS" in the ServiceNow menu |

## Development Guidelines for AI Agents

### General
- **Never edit files under `src/fluent/generated/`** — these are auto-generated by `now-sdk`.
- Keep the ServiceNow scope (`x_159204_guss`) consistent in all artifact definitions.
- All server-side logic lives in `src/fluent/`; all client-side logic lives in `src/client/`.

### Frontend (React/TypeScript)
- Components go in `src/client/components/`. Each component gets its own `.tsx` and `.css` file.
- Shared data types and API calls belong in `src/client/services/updateSetService.ts`.
- The app has no routing; it is a single-page tool rendered inside a ServiceNow UI page.

### Backend (ServiceNow Fluent)
- New server-side artifacts (Script Includes, UI Pages, etc.) go in the appropriate `src/fluent/` subdirectory.
- Use the `Now.ID[...]` pattern for `$id` fields to maintain stable artifact identity across deployments.
- `GussAjax` uses an inline string for the server script (`gussAjaxScript`) because ServiceNow executes it in a Rhino JS engine — do not use modern JS syntax inside that string.

### Build & Validate
- Run `npm run build` after any changes to verify the TypeScript compiles cleanly before deploying.
- Run `npm run deploy` only when connected to a target ServiceNow instance.
